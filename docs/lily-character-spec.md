> 状态：草案 v1，2026-11-05。定稿前所有尺寸/色值都可能调整。

## 1. 一句话设定

**Lily（莉莉）**，二十岁上下的元气少女，住在屏幕右下角。白天陪你上课、盯进度，晚上会犯困。话不多但说得准，回答不了就说"不知道"，不装懂。

- 性格：元气但不吵、好奇、有点较真
- 口癖：句尾偶尔带"呀""啦"；自称"我"，不说"本喵"这类第三人称动物腔
- 视觉关键词：暖、干净、亮而不刺眼（桌面常驻，不能抢注意力）

## 2. 参考来源与版权边界（重要）

参考图集：[RuiC-PoseAtlas](https://hruiccc.github.io/RuiC-PoseAtlas/)（姿势 288 组 / 衣装 1407 套 / 人像 1499 张）。

其声明为：图片版权归原作者（ギア / POSE-DB-01 · COSTUME-DB-01 · PORTRAIT-DB），**禁止转售与再分发图片数据本身**，且未授予商业使用许可。

因此本项目的规定是：

| 允许 | 禁止 |
|---|---|
| 作为姿势、比例、穿搭结构的**参照**，看完自己画 | 把图集里的任何 PNG/WebP 复制进仓库或安装包 |
| 在文档里记录所参考条目的 ID 与名称 | 直接把参考图当素材使用、二次分发、用于对外宣传物料 |
| 提炼通用造型语言（站姿、坐姿、学院风穿搭） | 复刻某一张具体图像的人物长相 |

结论：**仓库里出现的每一根线都由我们自己画**。图集只解决"姿势对不对、比例像不像人"的问题。

## 4. 体型与画布

### 4.1 比例

**3.2 头身**（不是 1:1 真人比例，也不是 2 头身的大头娃娃）。理由：

- 320×320 窗口里，3.2 头身时头部约 100px，五官够看清；
- 2 头身虽然更"可爱"，但手臂和腿的关节几乎没地方做动作，蹦跳会显得像方块在平移；
- 7 头身写实比例在这个尺寸下脸只有 40px，表情完全看不见。

## 6. 分层结构（决定 P1-03 能不能做表情）

单文件 `src/assets/lily/lily-base.svg`，内部用 `<g id>` 分组；JS 通过 `getElementById` 控制显隐与变形。

```
#root
├─ #shadow            地面椭圆，透明度随状态变
├─ #hair-back         后发（含马尾）
├─ #body
│   ├─ #legs
│   ├─ #skirt
│   ├─ #torso         衬衫 + 针织外套
│   └─ #arms
│       ├─ #arm-l
│       └─ #arm-r
├─ #head
│   ├─ #face
│   ├─ #ears
│   ├─ #brow-l / #brow-r
│   ├─ #eye-l / #eye-r
│   │   ├─ #eye-l-white
│   │   ├─ #eye-l-iris
│   │   ├─ #eye-l-lid        ← 上眼睑，闭上时用 scaleY 压
│   │   └─ #eye-l-shine
│   ├─ #mouth
│   ├─ #blush-l / #blush-r
│   └─ #hair-front     刘海 + 侧发
└─ #props              汗滴、星星、zzz、音符，默认 display:none
```

**工程约束**：当前渲染层用 `<img src>` 加载素材（`media-renderer.js`），img 里的 SVG 不能执行脚本，JS 也拿不到内部节点。所以：

- **P1-02 阶段**：只用 SVG 自带的 SMIL 动画（呼吸、眨眼），能直接跑在 `<img>` 里，不改渲染层；
- **P1-03 阶段**：把 `<img>` 换成内联 `<svg>` 注入（读文件文本 → `innerHTML`），才谈得上参数化表情。

这条约束写在这里，免得后面误以为"画好分层图 JS 就能直接控制"。

## 7. 表情参数表

表情 = 眼 × 眉 × 嘴 × 腮红 的组合，不做逐张画。

| 维度 | 取值 | 说明 |
|---|---|---|
| 眼 | `open` / `half` / `closed` / `smile`(弯月) / `star`(高光星形) | 闭合用 `scaleY(0.08)` 压眼睑，不换图 |
| 眉 | `neutral` / `up`(惊讶) / `sad`(内低外高) / `angry`(内高外低) / `focus`(微皱) | 旋转 ±8° |
| 嘴 | `smile` / `open`(说话) / `small`(一条短线) / `o`(惊讶) / `pout`(鼓嘴) / `wavy`(为难) | 说话时用 `open` 上下缩放模拟口型 |
| 腮红 | `0` / `1` / `2` | 透明度 0 / 0.45 / 0.8 |

常用组合（一期先做这 8 个）：

| 名字 | 组合 | 用在哪 |
|---|---|---|
| 平静 | open + neutral + small + 0 | idle |
| 开心 | smile + up + smile + 1 | 打招呼、完成任务 |
| 大笑 | closed + up + open + 2 | 庆祝 |
| 思考 | half + focus + small + 0 | thinking |
| 专注 | open + focus + small + 0 | working |
| 期待 | open + up + smile + 1 | waiting_user |
| 为难 | half + sad + wavy + 1 | error / blocked |
| 困 | closed + sad + small + 1 | sleeping |

表情帧是**独立叠加层**（`#pet-sprite-expression`），不是替换 `idle.png`：

- 只在当前素材等于默认帧时显示，点击/拖拽动画期间自动隐藏，不会出现「脸在叉腰、身体在欢呼」；

## 12. 落地记录（2026-11-05）

第一版**没有走手绘分层 SVG**，改用图片生成 + img2img 保持角色一致。原因见 [路线图 D1 修订](../LILY_ROADMAP.md)：

- 手绘分层 SVG 要达到可用完成度，成本在一周以上，且第一版必然反复返工；
- img2img 能在几分钟内给出"同一张脸、不同姿势"的成品，先把角色立起来；
- 代价是表情不能自由组合，只能按"预生成变体"的方式扩，因此 `P1-03` 改成 8 张表情变体的方案。

### 实际产出

| 文件 | 姿势 | 尺寸 | 用途 |
|---|---|---|---|
| `src/assets/default-pet/assets/idle.png` | 站立・双手扶腰（参考 P018） | 332×560 | 待机 |
| `src/assets/default-pet/assets/click.png` | 举臂 V 字欢呼（参考 P030） | 340×560 | 点击反馈 |
| `src/assets/default-pet/assets/drag.png` | 悬空・双臂张开（参考 P024 变体） | 342×560 | 拖拽 |

三张都在纯色浅底上生成，再用"从边缘做连通域泛洪 + 取最大前景连通块"的方式抠掉背景与生成水印，得到透明 PNG。抠图脚本逻辑保留在本文件第 12.1 节，换图时照做。

### 12.1 抠图做法（换素材时复用）

1. 从四条边做种子，泛洪所有"接近中性浅色"的像素（`min(r,g,b) >= 214` 且通道差 `<= 34`）；
2. 泛洪结果视为背景，取反得到前景；
3. 只保留包含画面中心的最大前景连通块（顺带去掉角落水印）；
4. 按前景包围盒裁切，等比缩放到高度 560，存 8-bit 透明 PNG。

### 12.2 已知差距（下一版要补）

- 比例实际约 **2.6 头身**，比规范里的 3.2 更 Q；好处是五官更清楚，暂时接受；
- 裙色偏亮绿（生成结果），与规范的薄荷绿 `#8FD3B6` 有偏差，换表情变体时统一回来；
- 三张图的马尾朝向不完全一致（都在人物右侧，但第二、三张位置偏高），动起来不易察觉，静帧对比能看出来；
- 没有呼吸与眨眼，纯静帧。`P1-04` 接上后才"活"。

### 12.3 生成参数存档

同一角色的一致性来自 img2img：先出 idle，再用它作为参考图（`input_fidelity: high`）生成 click 与 drag，提示词里固定"同角色、同画风、同服装配色"。

## 13. 闭眼帧与待机生命感（2026-11-05）

### 13.1 素材

| 文件 | 说明 | 尺寸 |
|---|---|---|
| `assets/idle-blink.png` | 闭眼帧，只用于眨眼，不参与任何规则 | 332×560 |

闭眼帧与 `idle.png` **同画布、同构图**，眨眼时只换眼睛，身体不动。做法是 img2img 生成同角色的闭眼立绘，再对齐。这些步骤已脚本化：`tools/align-expression-frame.py`。

```bash
python tools/align-expression-frame.py 生成图.png --out src/assets/default-pet/assets/idle-blink.png
```

1. 抠背景（连通域泛洪 + 取最大前景块，见 12.1）；
2. 先把新图等比缩到参考帧高度（332×560 的 560）——**必须先统一高度再量基准**，否则 45% 的「头部取景带」在大图上会落到不同位置，可能量到肩膀；
3. 量三个基准：头部最宽行宽度、头部最宽行 y、脚底 y；
4. 横向按「头宽比」缩放（这次 sx≈0.982），纵向按「头顶到脚底的距离比」缩放（sy≈1.025）；
5. 平移让头部最宽行落在 idle 的同一行，最后贴回 332×560 画布。

脚本输出的 `idle-blink.png` 与手工流程结果逐像素一致（可复现）。

**为什么要三个基准**：只按整体包围盒缩放，头会偏；只按头对齐，脚会浮空。头宽 + 脚底 + 头行同时对上，短时间的叠加才看不出跳动。

### 13.2 眨眼参数

| 参数 | 值 | 位置 |
|---|---|---|
| 首次延迟 | 1.6s | `src/renderer/pet/idle-life.js` |
| 间隔 | 2.6–6.4s 随机 | 同上 |
| 闭眼时长 | 92–118ms | 同上 |
| 连眨概率 | 16%，间隔 128ms | 同上 |

触发条件：当前渲染的素材 **等于默认帧**。点击、拖拽、视频、GIF 期间素材不是默认帧，会自动跳过，所以不会出现「举着手却在眨眼」的穿帮。

### 13.3 呼吸

CSS 动画，作用在 `#pet-sprite-stage`（`.lily-breathing` / `.lily-swaying`）：

- 呼吸：4.2s，`scale` 从 `1` 到 `1.008 × 1.016`，锚点在脚底；
- 重心：9.4s，`rotate` ±0.35°。

**不要**把呼吸写进 `#pet-sprite` 的 `transform`：状态类（`state-thinking` 等）已经在用 `transform` 做动效，写同一属性会互相覆盖。这就是为什么要多一层 stage。

### 13.4 已知限制

- 只有「睁/闭」两态，没有半闭眼（困倦）与眨眼时的眉毛联动；
- 闭眼帧的表情是「微笑张嘴」，与 idle 一致；如果以后做「思考」表情，需要各自配一张闭眼帧；
- 对齐是手算一次的，换立绘必须重跑第 13.1 节的流程。

### 14.2 生成流程

1. 以 `idle.png` 作参考图做 img2img（`input_fidelity: high`），提示词固定「同角色 / 同服装 / 同姿势 / 全身入镜」，只改表情一句；
2. 纯浅灰底生成（这批实测底色 207–215，比第一批暗），跑 `tools/align-expression-frame.py` 抠背景 + 三基准对齐；
3. 抠图阈值从 `min(r,g,b) >= 214` 放宽到 `190`，通道差 `34 → 24`——否则整张灰底会被当成主体，对齐系数直接算飞。脚本新增 `--bg-threshold` 参数备用。

对齐结果：头宽全部 319px、脚底全部 559 行，头部最宽行差 0–4px（`expect` 因为张嘴 11px，视觉无感），横向包围盒 2–330。

### 14.3 已知差距

- 八张是「同一姿势换脸」，不是可组合的分层表情；换姿势必须重新生成整套；
- `focused` 在缩到 120px 时略带「生气」观感，与 `error` 的 `troubled` 区分度靠光晕补；
- 每张表情都对应一张独立 PNG（约 240KB/张），八张合计约 1.9MB，比矢量方案重；
- 没有半闭眼中间态，眨眼与「困」之间切换是硬切。
